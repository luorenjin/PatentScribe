# PatentMate 安装与首次配置说明

## 1. 文档目的

本文档面向安装和首次使用 `PatentMate` 的同事，说明：

- 如何安装和启动
- 首次进入后应如何配置模型
- 默认模式下如何使用阿里百炼
- 如何通过机器码申请授权码
- 如何使用授权码生成工具

如果你是开发同事，同时请配合阅读：

- `docs/DEVELOPMENT_GUIDE.md`
- `docs/RELEASE_DELIVERY_CHECKLIST.md`
- `docs/ENVIRONMENT_SETUP_GUIDE.md`

## 2. 安装前准备

开始前请确认以下事项：

- 已拿到安装包或可执行文件
- 已拿到本项目交付说明
- 已确认本次交付默认使用哪种模型模式
- 如果需要自配模型，已准备好百炼 API Key
- 如果启用了强制激活，已知晓授权申请联系人

## 3. 安装与启动

## 3.1 安装

Windows 环境下通常使用安装包完成安装。

安装完成后，启动应用：

- 开始菜单中找到 `PatentMate`
- 或双击桌面快捷方式

首次启动时，应用会进入初始化和配置流程。

## 3.2 首次启动后会看到什么

首次进入通常会看到以下内容：

1. 首次配置弹窗
2. 模型提供商选择
3. 文件上传首页
4. 如果启用了强制激活，上传分析前可能需要先完成激活

## 4. 首次模型配置

本项目要求员工/用户自行配置模型 API 提供商及 API Key。当前支持以下三类大模型接入：

1. **通义千问 (Qwen)**: 推荐。国内访问极其稳定，对中文专利交底书的理解、扩写和表格生成能力非常平衡。建议 Model ID 填 `qwen3.6-plus`。
2. **Google Gemini**: 适合长文本或多模态（解析附图）场景。建议 Model ID 填 `gemini-3-flash-preview`。
3. **OpenAI**: 行业标准。支持 GPT-4o 等系列。
4. **自定义端点**: 支持任何兼容 OpenAI 协议的接口。

## 4.1 配置步骤

1. 打开应用右上角 `设置` (Settings)。
2. 在 `模型提供商` 中选择您所拥有的 API 类型。
3. 填写以下参数：
   - `API Key`: 必填。
   - `API Endpoint`: 接口地址（切换提供商时通常会自动填入默认值）。
   - `Model ID`: 目标模型标识码。
4. 点击“保存并载入”。

> **注意**：本项目不提供默认 API Key。您必须自行配置才能使用 AI 功能。如果您没有 Key，解析功能将被拦截。

## 5. 阿里百炼 API Key 获取方法 (推荐)

## 5.1 官方入口

阿里百炼官方 API Key 文档：

- https://help.aliyun.com/zh/model-studio/get-api-key/

本项目代码中的百炼控制台入口也指向：

- https://bailian.console.aliyun.com/cn-beijing?tab=model#/api-key

## 5.2 获取步骤

建议按下面操作：

1. 登录阿里云账号
2. 打开百炼控制台
3. 切换到目标地域，建议 `华北 2（北京）`
4. 进入 `API Key` 页面
5. 创建 API Key
6. 建议先放在 `默认业务空间`
7. 创建成功后立即复制保存

注意：

- API Key 明文通常只完整显示一次
- 丢失后只能重建或重置，不能再次查看原文

## 5.3 在本软件中的填写方式

进入 `设置 -> 通义千问 (Qwen)` 后填写：

- `API Key`：你申请到的百炼 Key
- `API Endpoint`：`https://dashscope.aliyuncs.com/compatible-mode/v1`
- `Model ID`：`qwen3.6-plus`

保存后即可开始使用。

## 6. 首次激活说明

如果当前版本启用了强制激活，那么在上传文件分析前，需要先完成授权。

当前代码里真正可闭环的授权方式是：

- `机器码授权激活`

应用里虽然可能显示“企业邮箱激活”入口，但当前仓库实现中该路径仍是模拟逻辑，不应作为正式交付流程使用。

因此，实际交付和支持时，请统一采用：

- 获取机器码
- 申请授权码
- 导入授权码

## 7. 通过机器码获取授权码的流程

## 7.1 使用者侧：获取机器码

在应用中可以通过两种方式查看机器码：

1. 打开 `设置`
   - 在授权信息区域查看 `本机机器码`
2. 在激活弹窗中查看
   - 进入 `机器码授权激活`
   - 复制显示的机器码

机器码格式类似：

```text
ABCD-1234-EF56-7890
```

实际值由客户端自动生成，不需要手工计算。

## 7.2 使用者侧：提交授权申请

把机器码发送给授权负责人或支持邮箱。

当前界面中的默认支持邮箱来自：

- `VITE_ACTIVATION_SUPPORT_EMAIL`

如未单独配置，代码默认值为：

```text
support@patentmate.ai
```

部分界面或交付说明中也可能指定其他联系邮箱，应以本次交付要求为准。

建议发送内容至少包括：

- 使用人姓名
- 部门/项目组
- 机器码
- 申请有效期需求

可参考模板：

```text
主题：PatentMate 授权申请

姓名：张三
部门：研发一部
机器码：ABCD-1234-EF56-7890
申请有效期：2026-12-31
备注：用于专利交底书撰写与测试
```

## 7.3 支持侧：生成授权码

授权负责人拿到机器码后，使用仓库中的授权码生成工具生成 License 文本，再回传给申请人。

生成工具源码位置：

```text
scripts/keygen/
```

构建命令：

```bash
yarn build:keygen
```

构建完成后，工具默认产出到：

```text
dist/keygen.exe
```

## 7.4 使用者侧：导入授权码

拿到授权码后：

1. 打开激活窗口
2. 切换到 `机器码授权激活`
3. 将收到的整段 License 文本粘贴到输入框
4. 点击 `导入并激活`

如果机器码匹配且授权码有效，应用会提示激活成功。

## 8. 授权码生成工具使用说明

## 8.1 工具作用

`keygen` 工具用于把：

- 机器码
- 到期日期

生成一个带签名的 License 字符串，供客户端导入验证。

当前客户端验证逻辑要求的 License 结构是：

1. 内层 JSON：包含 `machineCode` 和 `expiryDate`
2. 使用 RSA 私钥签名
3. 外层包装为 `data + signature`
4. 最终再整体做 Base64 编码

因此，授权人员不应手工拼接 License，必须使用工具生成。

## 8.2 构建工具

在仓库根目录执行：

```bash
yarn build:keygen
```

成功后会得到：

```text
dist/keygen.exe
```

## 8.3 交互式使用

直接运行：

```bash
dist\keygen.exe
```

程序会依次提示输入：

1. 机器码
2. 到期日期

如果到期日期留空，工具默认使用：

```text
2026-12-31
```

生成成功后，工具会输出完整 License 文本。将这段文本完整复制给申请人即可。

## 8.4 命令行参数方式

也可以直接带参数执行：

```bash
dist\keygen.exe ABCD-1234-EF56-7890 2026-12-31
```

参数顺序为：

1. `machine_code`
2. `expiry_date`

如果只传机器码，不传到期日，工具仍会提示输入到期日。

## 8.5 返回结果如何使用

工具输出的是一整段 Base64 文本，例如：

```text
eyJkYXRhIjoiLi4uIiwic2lnbmF0dXJlIjoiLi4uIn0=
```

使用方法：

- 不要改动内容
- 不要换行裁剪
- 原样发送给用户
- 用户在激活窗口中整段粘贴导入

## 8.6 当前工具的重要风险提示

当前仓库中的 `scripts/keygen/src/main.rs` 使用了内嵌私钥。

这意味着：

- 该工具不应随普通客户端一起外发
- 不应交给无签发权限的普通使用者
- 私钥材料应由少数授权负责人保管

建议：

- 对外分发时不要附带 `keygen.exe`
- 不要把私钥文件和签发工具发给终端使用者

## 9. 首次使用建议流程

推荐按下面顺序完成首次使用：

1. 安装并启动 PatentMate
2. 进入设置，填入 API Key、Endpoint、Model ID
3. 如果上传前提示需要激活，则复制机器码申请授权
4. 导入授权码
5. 上传 `.docx/.pdf/.txt/图片` 进行首次分析
6. 成功后保存到工作台并测试导出

## 10. 常见问题

## 10.1 如果 AI 调用报错
优先检查：
- Key 是否复制完整
- Endpoint 是否正确（百炼通常为 `https://dashscope.aliyuncs.com/compatible-mode/v1`）
- Model ID 是否填写正确
- 账号余额是否充足
- 账号所在地域和权限是否符合要求

## 10.3 导入授权码失败怎么办

优先检查：

- 是否复制了完整 License 文本
- 机器码是否与申请时一致
- 是否超过到期日
- 客户端公钥和签发私钥是否匹配

如果仍有问题，应联系授权签发负责人重新生成。

## 10.4 邮箱激活为什么不可用

因为当前仓库代码中邮箱验证码激活流程仍是模拟实现，并未形成正式服务端闭环。实际交付请统一使用机器码授权方式。
